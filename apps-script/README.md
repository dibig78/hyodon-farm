# Apps Script 배포 순서 (5분)

홈페이지에서 들어온 주문을 구글 시트에 자동으로 쌓이게 하는 부분입니다.
**한 번만 하면 되고, 이후에는 홈페이지 `CONFIG.APPS_SCRIPT_URL`에 주소만 넣으면 끝납니다.**

## 준비

- 주문 시트: https://docs.google.com/spreadsheets/d/1iMgUyWzZopJ8KZfKmVV93FtNlLao4XFNtCK3xekgfeA/edit
- 이 시트는 `dibig788@gmail.com` 계정에 있습니다. **그 계정으로 로그인**한 상태에서 진행하세요.

## 순서

1. 위 시트를 엽니다.
2. 메뉴에서 **확장 프로그램 → Apps Script** 를 누릅니다.
3. 왼쪽 `Code.gs` 내용을 모두 지우고, 이 폴더의 `Code.gs` 내용을 **그대로 붙여넣고 저장**(Ctrl+S / ⌘+S)합니다.
   - 시트 ID는 이미 코드 안에 들어 있습니다. 수정할 필요 없습니다.
   - 새 주문을 메일로도 받고 싶으면 코드 위쪽 `NOTIFY_EMAIL = ''` 에 메일 주소를 넣으세요(선택).
4. 오른쪽 위 **배포 → 새 배포** 를 누릅니다.
5. 왼쪽 톱니바퀴(유형 선택) → **웹 앱** 을 고릅니다.
6. 설정을 아래처럼 맞춥니다.
   - 설명: `효돈농원 주문 접수`
   - 다음 사용자 권한으로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** ← 반드시 ‘모든 사용자’
7. **배포** → 처음이면 **액세스 승인** 창이 뜹니다. 본인 계정 선택 → “고급” → “(안전하지 않음)으로 이동” → **허용**.
   - 본인이 만든 스크립트라 경고가 뜨는 것이 정상입니다. 시트에 주문을 쓰기 위한 권한입니다.
8. 완료되면 **웹 앱 URL** 이 나옵니다. `https://script.google.com/macros/s/…………/exec` 형태입니다. 복사하세요.
9. 브라우저 새 탭에 그 주소를 붙여 열어 봅니다.
   - `{"ok":true,"service":"효돈농원 주문 접수", ...}` 처럼 나오면 정상입니다.
10. `index.html` 의 `CONFIG.APPS_SCRIPT_URL` 에 그 주소를 붙여넣고 저장 → GitHub에 올리면 끝입니다.

## 배포 후 확인

1. 홈페이지에서 테스트 주문을 한 번 넣어 봅니다(받는 분 이름에 `테스트`라고 적기).
2. 시트 맨 아래에 주문일시(한국 시간)와 함께 한 줄이 생기면 성공입니다.
3. 확인한 테스트 줄은 시트에서 지우면 됩니다.

## 관리자 페이지 (admin.html)까지 쓸 때

주문 목록을 보고 입금확인·송장번호를 넣는 관리자 페이지는 따로 배포가 필요 없습니다.
저장소의 `admin.html`이 이미 GitHub Pages에 올라가면 주소는 `https://dibig78.github.io/hyodon-farm/admin.html`입니다.
홈페이지에는 링크를 걸지 않았습니다. 손님에게 주소를 공유하지 마세요.

1. `Code.gs` 위쪽에 본인 Gmail(`OWNER_EMAIL`)과 관리자 키(`ADMIN_KEY`)를 넣고 저장합니다.
   (두 값 모두 GitHub 저장소에는 빈칸으로 두고, Apps Script 편집기에서만 입력하세요.)
2. 배포 설정을 아래처럼 맞춥니다.
   - 다음 사용자 권한으로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** ← 키로 확인하므로 구글 로그인이 필요 없습니다
3. 배포 관리에서 새 버전으로 배포하고, 나온 `/exec` 주소를 복사합니다.
4. `admin.html`을 열고 위쪽 입력칸에 그 `/exec` 주소와 관리자 키를 붙여넣고 **저장하고 주문 불러오기**를 누릅니다.
   (주소와 키는 이 기기 브라우저에만 저장됩니다. 키를 모르면 목록이 열리지 않습니다.)

왜 키 방식인가: 관리자 페이지는 홈페이지에서 `fetch`로 웹앱을 부르는데, 구글 계정 로그인 방식은
브라우저가 타 사이트로의 로그인 정보 전달을 막아서 목록이 안 떴습니다(2026-11-14 확인).
그래서 키 방식으로 바꿨습니다. 키가 없으면 목록은 `"ok":false`로 막힙니다.
주문 접수(`index.html`)용 배포도 액세스 **모든 사용자**라서, 두 배포 모두 같은 액세스 설정입니다.
배포를 새로 만들 때 설명에 용도(주문 접수용/관리자용)를 적어두면 헷갈리지 않습니다.

## 코드를 고친 뒤에는

Apps Script 편집기에서 **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 눌러야 홈페이지에 반영됩니다.
(저장만 하면 반영되지 않습니다.)

## 잘 안 될 때

| 증상 | 확인할 것 |
| --- | --- |
| 주문 후 “자동 접수에 실패했습니다” | `CONFIG.APPS_SCRIPT_URL` 주소가 `/exec`로 끝나는지, 배포 액세스가 **모든 사용자**인지 |
| 주소를 열면 로그인 화면이 나옴 | 액세스 권한이 ‘모든 사용자’가 아님 → 배포 관리에서 수정 |
| 관리자 페이지에서 “불러오기 실패: Failed to fetch” | 수정한 admin.html이 라이브에 아직 안 올랐거나 브라우저 캐시입니다. 주소를 `admin.html?v=2`처럼 붙여서 최신본을 받으세요. 키를 빼고 부르면 서버가 `"ok":false`를 돌려줍니다. |
| 시트에 줄이 안 쌓임 | 스크립트를 연 계정과 시트 소유 계정이 같은지(`dibig788@gmail.com`) |
| 상품명·주소가 한 칸씩 밀림 | 시트 1행 헤더가 지워졌는지 확인 (헤더가 비면 자동으로 다시 채워집니다) |
